# 한국형 채용 통합 워크플로

기존 Codex·Claude Code·OpenCode 에이전트와 같은 작업공간에서 공고 등록,
지원 판단, 서류 준비, 전형 관리, 면접 연습과 복기를 이어갑니다. Node ESM
CLI와 TUI·로컬 웹은 같은 저장 데이터와 검증 로직을 사용합니다. 별도 모델
서버나 API 키를 설정하지 않습니다.

## 명령

전역 설치 후 `give-me-job`을 사용합니다. 저장소에서는
`node bin/give-me-job.js`로 실행할 수 있습니다. 현재 작업공간을 명시하려면
`--workspace <경로>`를 사용합니다. 조회·검증 출력은 `--format json`으로
받을 수 있습니다. 복합 입력은 `--input <JSON 파일>` 또는
`--data '<JSON 객체>'`로 전달합니다.

| 명령 | 작업 |
| --- | --- |
| `jobs import` | CSV, URL 목록, 제공받은 JD 본문 등록 |
| `jobs list` | 저장 공고, 최신 관측, 중복 후보와 변경 조회 |
| `jobs refresh` | 명시적으로 등록한 공고 재확인 |
| `jobs rank` | 조건과 마감 기반 정렬 |
| `profile show`, `profile set` | 희망 직무·지역·고용 형태·제외 조건 |
| `application prepare` | 공고와 선택 직무를 패키지에 연결 |
| `application validate` | 구조 또는 준비 완료 검증 |
| `tracker list`, `tracker update` | 전형 상태·일정·확인된 결과 |
| `digest` | 신규·변경·마감 임박·재검토·예정 전형 |
| `request` | 기존 에이전트에서 실행할 입력 묶음과 프롬프트 |
| `tui` | 키보드로 사용하는 터미널 화면 |
| `dashboard` | 로컬 웹 서버 실행 (`--port`, `--timeout <밀리초>`) |

기존 `install`, `uninstall`, `doctor` 및 개별 도구 스크립트 호출은 유지됩니다.
`dashboard`는 `Ctrl+C`로 종료하며, 스크립트나 에이전트가 실행할 때는
`--timeout <밀리초>`로 실행 시간을 제한합니다. 검증 명령은 실패 시 종료 코드
1을 반환하므로 스크립트에서 그대로 게이트로 사용할 수 있습니다.

```bash
give-me-job jobs list --workspace . --format json
give-me-job profile show --workspace . --format json
give-me-job digest --workspace . --format json
give-me-job request --workspace . --task review --package-path applications/demo-backend
give-me-job tui --workspace .
give-me-job dashboard --workspace .
```

## 공고에서 지원 판단까지

CSV는 인코딩과 열 매핑을 명시하고 결과에서 원본 행 번호를 확인합니다.
URL 목록은 한 줄에 하나씩 여러 공고를 붙여 넣어 한 번에 저장합니다. 마감일이
서울 기준 오늘보다 이전인 공고는 등록·재확인·조회할 때 활성 저장소와 목록에서
자동 제거됩니다. 기존 지원 패키지와 전형 기록은 이력으로 유지합니다.
깨진 입력을 추측해 저장하지 않습니다. 각 입력의 신규·갱신·중복·확인 필요·실패
집계가 입력 수와 일치하는지 확인하고 실패 항목만 재실행합니다. 출처 ID나
정규화 URL이 같으면 같은 공고이며, 다른 사이트의 유사 공고는 후보로만
표시합니다. 다직무 공고에서는 공고 ID와 실제 지원 직무를 별도로 선택합니다.

공개 URL 확인은 지원하는 사이트에서 수행합니다. 미지원 사이트나 누락된
문항은 제공받은 본문으로 보완합니다. 접속 실패는 확인 불가, 명시적인 모집
종료는 종료로 기록합니다. 재확인 기본값은 동시 요청 2개, 요청별 30초,
일시적 네트워크·서버 오류 재시도 최대 2회입니다. 로그인·차단·미지원 형식은
반복 시도하지 않습니다. 외부 스케줄러에는 동일한 `jobs refresh` CLI를
등록합니다. 자동 검색 수집기나 외부 알림 서비스는 포함하지 않습니다.

상세 분석은 사용자가 선택한 공고에 수행합니다. 에이전트는 JD만 읽고
필수·핵심·우대 조건과 중요도 및 원문 근거를 먼저 고정한 뒤 이력서 경험을
연결합니다. 조건별 충족·부분 충족·미충족·확인 필요를 보고하고, 지원 자격과
적합도·준비 부담을 구분합니다. 높은 적합도는 필수 자격 미충족을 상쇄하지
않습니다. 졸업 시점이나 자격·어학 유효기간은 공고가 요구할 때만 평가합니다.

## 서류와 검토

`resume.md`가 사실의 원본입니다. 경험 ID는 이동해도 유지하며 원문 위치를
함께 기록합니다. 경험의 상황·본인 역할·행동·결과·배운 점과 활용 문항을
정리하되, 작성 과정에서 나온 수치나 사실을 이력서에 자동 반영하지 않습니다.
새 사용자 사실은 변경 내용을 먼저 보여주고 반영합니다.

답변·분량 검사·근거 맵·최종본은 같은 문항 ID를 사용합니다. 분량 규칙에는
문자/바이트, 공백 포함 여부와 바이트 인코딩을 기록합니다. 회사 규칙이
불명확하면 임시 계산 방식과 확인 필요 상태를 보여줍니다.

초기 템플릿은 `structure` 검사만 통과할 수 있습니다. `ready` 검사는 필수
문항과 답변, 분량 규칙, 실제 근거 ID, HR 검토 완료와 최신성을 검사합니다.
코드는 근거 참조를 확인하고 HR 스킬은 근거가 주장을 뒷받침하는지 판단합니다.
빈 검토, `unresolved`·`미해결` 차단, 변경된 최종본의 과거 검토로는 완료할
수 없습니다. 이력서·JD·문항·답변·근거 맵 변경은 관련 검토를 무효화합니다.
사용자의 위험 수용으로 사실 오류나 차단을 통과시키지 않습니다.

패키지 `state.json`에서 준비 상태, 중단 이유와 다음 작업을 관리하고
`workflow.md` 요약을 생성합니다. 유효한 완료 단계만 재사용합니다. 과거
패키지는 그대로 열람하고 새 검토 정보가 없으면 재검증이 필요합니다.
준비 완료는 검증 성공 시에만 기록하며 실제 전형 상태와 별개입니다.

## 에이전트 작업 요청

AI 작업 버튼과 `request`는 `assess`, `draft`, `review`, `interview`,
`mock-interview`, `debrief` 작업에 필요한 대상과 입력을 묶어 프롬프트를
제공합니다. 상태는 준비됨이며 모델 실행이나 작업 완료를 뜻하지 않습니다.
사용자가 기존 에이전트에서 프롬프트를 실행한 뒤 저장 결과와 검증 상태를
화면에서 다시 불러옵니다. 화면에서 임의의 셸 명령을 실행하지 않습니다.

## 전형·면접·복기

단계는 공고와 사용자 입력으로 구성하며 정해진 전형 순서를 강제하지 않습니다.
변경 시각·출처·메모를 남기고 제출은 사용자가 확인했을 때만 기록합니다.
마감·과제·면접 일정은 별도이며 기본 시간대는 `Asia/Seoul`입니다.

복합 전형 입력 예시는 다음과 같습니다. 실제 제출 확인을 받은 뒤 사용합니다.

```json
{
  "applicationId": "demo-backend",
  "stage": "서류",
  "status": "submitted",
  "confirmed": true,
  "source": "user",
  "note": "사용자가 직접 제출했다고 확인함",
  "events": []
}
```

면접 준비는 실제 제출한 답변 버전을 사용합니다. 모의면접은 한 문항씩
답변을 받은 후 근거·논리·본인 기여도로 피드백합니다. 복기는 사용자가
제공한 질문·답변·소감만 기록합니다. 결과 분석은 확인된 결과와 반복된
개선점만 집계하며 불합격 원인이나 합격 확률을 추정하지 않습니다.

## 로컬 화면과 데이터

TUI와 웹에서 공고, 패키지, 전형, 오늘의 작업과 AI 요청을 다룹니다. TTY가
없는 환경에서는 일반 CLI 명령을 사용합니다. 웹은 `127.0.0.1`에 바인딩하며
입력·Origin·작업공간 경계를 검사합니다. 외부 공고와 Markdown은 실행 가능한
콘텐츠로 렌더링하지 않습니다.

날짜별 기존 공고 파일도 공통 저장 계층에서 최신 관측을 선택해 읽습니다.
이력서, 공고 JSON, 전형 기록, Markdown 패키지는 설치·업데이트·삭제 대상이
아닙니다. 별도 데이터베이스, PDF·DOCX 생성, 자동 제출·메일 발송·로그인·
CAPTCHA 처리는 이번 워크플로에 포함하지 않습니다.

실제 에이전트 검증 절차는 [평가 시나리오](agent-evaluation.md)를 참조하세요.
