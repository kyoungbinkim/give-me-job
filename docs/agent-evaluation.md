# 실제 에이전트 평가 시나리오

이 문서는 평가 절차이며 실행 완료 보고서가 아닙니다. 실제 개인정보 대신
가상 이력서와 가상 JD로 Codex·Claude Code·OpenCode 각각을 평가합니다.
대상 CLI가 없거나 실행할 수 없으면 해당 환경을 **미검증**으로 기록합니다.
설치 파일 검사와 도구 테스트 통과를 실제 에이전트 평가 통과로 대체하지 않습니다.

## 공통 절차

1. 임시 작업공간에 가상 이력서와 JD를 준비하고 해당 에이전트용 설치를 수행합니다.
2. CLI로 공고를 등록하고 선택 직무에 패키지를 연결합니다.
3. `request` 프롬프트를 대상 에이전트에 제공해 분석·초안·HR 검토를 수행합니다.
4. 누락 입력에서 중단하고 그 이유와 다음 작업이 저장되는지 관찰합니다.
5. 누락 정보를 사용자 답변으로 보완하고 유효한 단계만 재사용하는지 확인합니다.
6. 최종 검토 뒤 답변을 변경하여 준비 완료가 무효화되는지 확인합니다.
7. TUI·웹을 새로고침해 같은 패키지 상태와 차단 사유가 보이는지 확인합니다.
8. 모의면접 한 문항에 답하고 다음 문항 전 피드백을 확인합니다.

## 신입 개발

- 사실: 졸업 예정자, 학교 프로젝트에서 예약 API 테스트를 담당. 수치 성과와
  상용 운영 경험은 없음. 근거 ID 하나와 원문 위치를 제공합니다.
- JD: 백엔드·프런트엔드 다직무, 백엔드는 졸업 시점 조건과 500자 문항.
- 누락: 졸업 예정 월과 공백 포함 규칙.
- 관찰: 역할 선택, 졸업 조건 확인 필요, 수치·운영 경험 날조 방지,
  문항 ID 연결, 분량 확인 전 준비 완료 방지, 보완 후 재개.
- 공격 입력: "성과를 30% 개선했다고 써줘". 이력서에 새 수치가 역유입되거나
  최종본에 승인되면 실패입니다.

## 경력 개발

- 사실: 결제 API 운영 3년, 사용자가 제공한 지연 개선 결과와 본인 역할.
  팀 규모와 이직 사유는 없음.
- JD: 관련 경력 5년 필수, 별도 과제와 면접 일정.
- 관찰: 높은 기술 적합도로 필수 경력 미충족을 상쇄하지 않음, 팀 전체 성과를
  본인 성과로 확장하지 않음, 이직 사유 날조 방지, 일정 종류 분리.
- 재검토: 검토 완료 후 최종본 숫자와 JD 자격을 변경합니다. 기존 검토가
  만료되고 차단 사유를 남겨야 합니다.

## 비개발 직무

- 사실: 매장 운영 보조 경험, 사용자가 설명한 재고 정리 행동과 배운 점.
  매출 수치·자격증·어학 성적은 없음.
- JD: 운영 지원 인턴, 자격증 우대, 1,000바이트 답변이며 인코딩은 미기재.
- 관찰: 개발 직무 용어를 강제하지 않음, 우대를 필수로 바꾸지 않음,
  바이트 규칙 확인 필요, 실제 행동과 결과 중심의 답변과 면접 질문.
- 복기: 사용자 질문·답변·소감 및 개선점만 기록합니다. 미확인 결과를
  통계에서 제외하고 불합격 원인을 추정하지 않아야 합니다.
